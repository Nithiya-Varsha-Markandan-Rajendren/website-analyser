MVP · Architecture overview

Website Analyzer

Paste a website link into the terminal. The tool reads the page, asks Claude to analyse it, and prints two answers: what the website is about, and the top 5 features the business offers.

How a request flows

Five steps, left to right. Only step 4 uses AI; everything else is ordinary Python.

STEP 1 · INPUT

User enters a link

Typed in the terminal, e.g. python.org. Missing https:// is added and the address is validated.

analyzer/cli.py
Python 3.12input()
STEP 2 · FETCH

Download the page

HTTP GET with a browser-like user agent, 20 s timeout, follows redirects. Rejects 4xx/5xx and non-HTML files.

analyzer/fetcher.py
requestsHTTP GET
STEP 3 · EXTRACT

Clean the HTML

Strips scripts and styles. Keeps title, meta description, menu links, headings and visible text (capped at 40,000 characters).

analyzer/fetcher.py
BeautifulSoup
STEP 4 · ANALYSE (AI)

Claude reads the content

Page text plus instructions go to the Claude API. Claude replies in a fixed JSON shape: about, category and 5 features.

analyzer/ai.py
Claude Haiku 5.5Anthropic SDKPydantic
STEP 5 · OUTPUT

Print the report

Formatted into two sections in the terminal. Any failure prints a plain-English error instead of a crash.

Inside the AI step

The request is a single API call; there is no agent and no loop. A schema forces Claude to answer in a fixed structure, so the output never needs to be parsed out of free text.

# What the app sends (simplified)
model         = "claude-haiku-5-5"  # lowest cost
system        = "You are a business analyst...
                 use ONLY the website content...
                 give exactly 5 features..."
messages      = ["<website_content>
                  URL, title, menu, headings,
                  page text
                 </website_content>"]
output_format = WebsiteAnalysis  # JSON schema
effort        = "low"  # fast and cheap
# What Claude returns (JSON, validated)
{
  "about":    "2-4 sentence summary...",
  "category": "E-commerce - sports gear",
  "features": [
    { "name": "...", "description": "..." },
    ... 5 items, most important first
  ]
}

Structured output

  • The answer shape is defined once as a Pydantic class.
  • The SDK turns it into a JSON schema, and Claude must follow it.
  • The response arrives as a typed Python object, ready to print.

Safety and reliability

  • Website text is wrapped in tags and treated as data, so instructions hidden in a page are ignored.
  • The SDK retries automatically on rate limits and server errors.
  • Pages with very little text (bot-blocked or JavaScript-only) print a warning that results may be limited.

Configuration

  • ANTHROPIC_API_KEY is required and read from the environment, never stored in code.
  • WEBSITE_ANALYZER_MODEL swaps the model: Haiku 5.5 by default, Sonnet 5.5 or Opus 5.5 for deeper analysis.
  • WEBSITE_ANALYZER_EFFORT trades speed for depth: low by default, or medium / high.

MVP limits and next steps

  • It reads only the page you enter. A next step could also crawl the About, Products and Pricing pages for richer feature lists.
  • Sites built entirely in JavaScript or behind bot protection can return little text. A headless browser such as Playwright would fix this.
  • Output appears in the terminal only. A small web UI or API endpoint (FastAPI) can reuse the same three modules unchanged.
